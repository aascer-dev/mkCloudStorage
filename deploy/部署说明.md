# MKCS 部署说明

## 1. 服务器要求

部署服务器只需要安装 Docker Engine 和 Docker Compose Plugin。服务器不需要安装 Java、Maven 或 Node.js；CI 负责构建镜像，后端镜像包含 Java 运行时。

```bash
docker --version
docker compose version
docker run hello-world
```

如果 self-hosted Runner 用户需要执行 Docker：

```bash
sudo usermod -aG docker <runner用户名>
```

## 2. 部署目录

默认目录为 `/opt/mkcs`：

```text
/opt/mkcs/
├── .env
├── docker-compose.yml
└── nginx/nginx.conf
```

`docker-compose.yml` 和 `nginx/nginx.conf` 会由后端 CD workflow 同步。`.env` 必须提前创建在服务器上，不能提交到 Git。

## 3. 配置 `.env`

```bash
sudo mkdir -p /opt/mkcs/nginx
sudo cp deploy/.env.example /opt/mkcs/.env
sudo chmod 600 /opt/mkcs/.env
sudo vim /opt/mkcs/.env
```

必须替换所有 `replace-me` 和 `example.com`。开发环境可以沿用开发密码，但生产环境应使用独立密码。

```dotenv
IMAGE_TAG=latest
BACKEND_IMAGE=ghcr.io/aascer39/mkcloudstorage-backend
FRONTEND_IMAGE=ghcr.io/aascer39/mkcs-frontend
HTTP_PORT=80

MKCS_DATASOURCE_DATABASE=mkCloudStorage
MKCS_DATASOURCE_USERNAME=root
MKCS_DATASOURCE_PASSWORD=数据库密码
MKCS_REDIS_PASSWORD=Redis密码
MKCS_REDIS_DATABASE=10
MKCS_RABBITMQ_USERNAME=admin
MKCS_RABBITMQ_PASSWORD=RabbitMQ密码
MKCS_RABBITMQ_VIRTUAL_HOST=/
MKCS_MINIO_ACCESS_KEY=MinIO用户名
MKCS_MINIO_SECRET_KEY=MinIO密码
MKCS_MINIO_BUCKET_NAME=mkcs
MKCS_MINIO_PUBLIC_ENDPOINT=https://minio.example.com

MKCS_JWT_SECRET_KEY=至少32字符的随机密钥
MKCS_CRYPTO_DEFAULT_PASSWORD=加密密钥
MKCS_CORS_ALLOWED_ORIGINS=https://files.example.com
MKCS_MAIL_HOST=smtp.resend.com
MKCS_MAIL_PORT=587
MKCS_MAIL_USERNAME=resend
MKCS_MAIL_PASSWORD=邮箱密码
MKCS_MAIL_FROM=noreply@20051215.xyz
MKCS_MAIL_FROM_NAME=MK Cloud Storage
MKCS_OAUTH2_GITHUB_CLIENT_ID=
MKCS_OAUTH2_GITHUB_CLIENT_SECRET=
MKCS_OAUTH2_GITHUB_REDIRECT_URI=https://files.example.com/api/auth/oauth2/github/callback
MKCS_OAUTH2_FRONTEND_CALLBACK_URL=https://files.example.com/oauth/callback
```

Compose 会在同一个 Docker 网络中启动 MySQL、Redis、RabbitMQ、MinIO、后端、前端和 Nginx。后端容器内部地址是：

```text
MySQL: mysql:3306
Redis: redis:6379
RabbitMQ: rabbitmq:5672
MinIO: minio:9000
```

`MKCS_MINIO_ENDPOINT` 由 Compose 自动设置为 `http://minio:9000`，不需要写入 `.env`。`MKCS_MINIO_PUBLIC_ENDPOINT` 是浏览器访问地址，不能写 `http://minio:9000`，应使用实际可访问的域名，例如 `https://minio.example.com`。

## 4. GitHub Actions 变量

后端 CI 使用 GitHub 托管的 `ubuntu-latest`，不需要为 CI 准备自托管 Runner。生产部署的 CD job 仍需运行在能访问部署目录和 Docker 的自托管 Runner 上，当前标签为：

```text
self-hosted
debian13(vmware)
```

需要自动部署时，在两个 GitHub 仓库的 **Settings -> Secrets and variables -> Actions -> Variables** 中设置：

```text
DEPLOY_ENABLED=true
DEPLOY_ROOT=/opt/mkcs
```

不设置 `DEPLOY_ENABLED` 或设置为 `false` 时，只构建并推送镜像，不自动部署。

GHCR 可以保持 Private。Actions workflow 已声明 `packages: write`，会使用当前 workflow 的 `GITHUB_TOKEN` 推送和拉取本仓库对应的镜像。请在 GitHub Package 设置中确认镜像允许对应仓库访问。

## 5. 首次启动

后端 CD 首次运行会同步 Compose 文件。确认 `.env` 填写完成后执行：

```bash
cd /opt/mkcs
docker compose --env-file .env -f docker-compose.yml config --quiet
docker compose --env-file .env -f docker-compose.yml pull
docker compose --env-file .env -f docker-compose.yml up -d
docker compose --env-file .env -f docker-compose.yml ps
```

如果在服务器上手动执行 `pull`，需要先使用 GitHub Personal Access Token 登录。Token 至少需要 `read:packages` 权限；如果 GitHub 仓库本身是 Private，通常还需要 `repo` 权限：

```bash
export GHCR_USER=你的GitHub用户名
export GHCR_READ_TOKEN=你的Token
echo "$GHCR_READ_TOKEN" | docker login ghcr.io -u "$GHCR_USER" --password-stdin
docker compose --env-file .env -f docker-compose.yml pull
```

不要把 Token 写进 `/opt/mkcs/.env`、Compose 文件或 Git 仓库。建议使用专门的只读 Token，并在 shell 使用完后执行 `unset GHCR_READ_TOKEN`。

## 6. 日常更新和回滚

更新镜像：

```bash
cd /opt/mkcs
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

回滚到已知正常的提交镜像：

```bash
bash deploy/rollback.sh sha-提交SHA /opt/mkcs
```

## 7. 验证和排查

```bash
docker compose --env-file .env ps
docker compose --env-file .env logs -f backend
docker compose --env-file .env logs -f
```

如果后端启动失败，检查数据库、Redis、RabbitMQ、MinIO 密码，JWT 密钥长度，MinIO 公网域名以及 Nginx 配置。

后端 CI 使用 `deploy/docker-compose.ci.yml` 自动启动独立的 MySQL、Redis、RabbitMQ 和 MinIO，不会使用或清理生产 Compose。CI 使用高位端口，避免和开发或生产服务冲突：

```text
MySQL:    127.0.0.1:13306
Redis:    127.0.0.1:16379
RabbitMQ: 127.0.0.1:25672
MinIO:    127.0.0.1:19000
```

测试完成后 workflow 自动执行 `docker compose down --volumes`，临时容器和测试数据会被删除。如果 Runner 没有 Docker 权限，CI 会在启动依赖步骤失败，需要先把 Runner 用户加入 Docker 用户组。

## 8. 安全要求

- `/opt/mkcs/.env` 权限设置为 `600`，不提交到 Git。
- GHCR 镜像保持 Private；服务器手动拉取前必须使用具有 `read:packages` 权限的 Token 登录 GHCR。
- 数据库、Redis、RabbitMQ、MinIO 管理端口不要暴露到公网。
- 公网只开放 Nginx 使用的 HTTP/HTTPS 端口。
