# MKCS 测试与集成验证

## 原则

测试按风险覆盖可观察行为，不能把编译通过当成功能验证。现有 Maven 多模块工程优先从根目录执行针对模块的命令；外部依赖不可用时如实报告未完成的集成验证。

## 测试分层

- 纯业务规则、DTO 校验、权限分支、哈希/分片计算使用快速单元测试，mock 外部对象存储、邮件和消息代理。
- Controller 测试覆盖统一响应、参数错误、未登录、403 和关键成功路径。
- 集成测试覆盖 MySQL Mapper/XML、Redis TTL/原子行为、MinIO 上传下载、RabbitMQ 重试和完整 Spring 配置。优先使用隔离的测试 profile、容器或受控本地服务，不共用开发数据。
- 数据库迁移必须从空库及已有库路径验证；项目未配置自动迁移工具时，测试须明确执行的 SQL 顺序，不能假设应用自动运行脚本。

## 文件领域重点

上传测试覆盖普通上传、秒传、随机位置校验失败、分片续传、缺片、重复分片、取消清理、权限下载和最后引用删除。断言 MySQL 元数据、Redis 短期状态和 MinIO 对象三者的最终状态。

## 执行与报告

优先运行最小相关测试，再运行 `mvnw.cmd -B test` 或可用的模块测试。不要提交真实服务凭据或依赖本机残留状态；报告实际命令、结果与未运行的外部依赖测试原因。
